\subsection{Dijkstra's Algorithm (Weighted Shortest Path)}

\textbf{Dijkstra's Algorithm} is a greedy algorithm that finds the shortest path from a source vertex to \textbf{all other vertices} in a weighted graph. It uses a \textbf{min-heap (priority queue)} to always process the vertex with the smallest known distance next.

To implement this, we use the following code:

\begin{verbatim}
public class Dijkstra {
    Map<Vertex, List<Vertex>> adjacencyList;
    public Dijkstra(Map<Vertex, List<Vertex>> adjacencyList) {
        this.adjacencyList = adjacencyList;
    }
    public Map<Vertex, Integer> shortestPath(Vertex src) {
        Map<Vertex, Integer> shortest = new HashMap<>(); // Vertex -> shortest distance
        PriorityQueue<Vertex> minHeap = new PriorityQueue<>();
        minHeap.add(new Vertex(0, src)); // Start with source, distance 0
        while (!minHeap.isEmpty()) {
            Vertex curr = minHeap.peek();
            minHeap.remove(); // Pop vertex with smallest distance
            if (!shortest.containsKey(curr.name)) {
                shortest.put(curr.name, curr.weight); // Finalize shortest distance
                for (Vertex neighbor : adjacencyList.get(curr.name)) {
                    if (!shortest.containsKey(neighbor.name)) {
                        // Add total accumulated distance (curr + edge weight)
                        minHeap.add(new Vertex(curr.weight + neighbor.weight, neighbor.name));
                    }
                }
            }
            // If already in shortest, skip — distance already finalized
        }
        return shortest;
    }
}
\end{verbatim}

\begin{itemize}
  \item \texttt{shortest}: maps each vertex to its shortest distance from the source
  \item \texttt{minHeap}: always processes the vertex with the smallest total weight next
  \item If a vertex is already in \texttt{shortest}, we skip it --- its shortest distance is already known
\end{itemize}
\textbf{Time Complexity:}
Each edge may add an entry to the heap, giving up to $E$ insertions. 

Pushing and popping from a heap costs $O(\log (E))$, since the heap can hold at most $E$ entries. This gives a total runtime of $O(E \log (E))$.

We can simplify further: since the maximum number of edges in a graph is $V^2$, we know $E \leq V^2$. Substituting: $O(E \log (E)) \leq O(E \log (V^2)) = O(E \cdot 2\log (V))$, which is equivalent to

\[
O(E \log (V)).
\]

\subsection{Prim's Algorithm (Minimum Spanning Tree)}

\textbf{Prim's Algorithm} is a greedy algorithm that finds the \textbf{Minimum Spanning Tree (MST)} of a weighted graph. Like Dijkstra's, it uses a \textbf{min-heap (priority queue)}, but instead of tracking total distance from the source, it selects the \textbf{smallest edge connecting a visited vertex to an unvisited vertex}.


\textbf{Input:} The graph must be \textbf{undirected} and \textbf{connected} (every vertex is reachable from every other vertex). The input graph may contain cycles.

\textbf{Output:} An \textbf{acyclic} spanning tree that connects all vertices with the minimum total edge weight.

To implement this, we use the following code:


\begin{verbatim}
public class Prim {
    Map<String, List<Vertex>> adjacencyList;
    public Prim(Map<String, List<Vertex>> adjacencyList) {
        this.adjacencyList = adjacencyList;
    }
    public int minimumSpanningTree(String src) {
        Set<String> visited = new HashSet<>(); // stores visted vertexes
        PriorityQueue<Vertex> minHeap = new PriorityQueue<>();
        int mstCost = 0;
        // Start with the source vertex, weight 0
        minHeap.add(new Vertex(0, src));
        while (!minHeap.isEmpty()) {
            // Get the smallest weight edge
            Vertex curr = minHeap.peek();
            minHeap.remove();
            // Only process if vertex hasn't been visited (prevents cycles)
            if (!visited.contains(curr.name)) {
                visited.add(curr.name);
                mstCost += curr.weight; // Add this edge's weight to the total MST cost
                // Push all edges to unvisited neighbors onto the heap
                for (Vertex neighbor : adjacencyList.get(curr.name)) {
                    if (!visited.contains(neighbor.name)) {
                        minHeap.add(new Vertex(neighbor.weight, neighbor.name));
                    }
                }
            }
        }
        return mstCost;
    }
}
\end{verbatim}

\begin{itemize}
  \item \texttt{visited}: tracks which vertices have been added to the MST
  \item \texttt{minHeap}: always processes the smallest edge weight connecting a visited vertex to an unvisited vertex
  \item If a vertex is already in \texttt{visited}, we skip it --- it is already part of the MST
\end{itemize}

\textbf{Key Difference from Dijkstra's:} In Dijkstra's, the heap stores the \textbf{total accumulated distance} from the source (i.e., \texttt{w1 + w2}). In Prim's, the heap stores only the \textbf{individual edge weight} (\texttt{w2}), because we want the cheapest single edge to grow the tree, not the cheapest total path.

\textbf{Time Complexity:}
The analysis is identical to Dijkstra's. Each edge may add an entry to the heap, giving up to $E$ insertions. Pushing and popping from a heap costs $O(\log E)$. Since $E \leq V^2$, $O(E \log E) = O(E \log V^2) = O(E \cdot 2\log V)$, which is equivalent to:

\[
O(E \log V).
\]

\subsection{Kruskal's Algorithm (Minimum Spanning Tree)}

\textbf{Kruskal's Algorithm} is another greedy algorithm that finds the \textbf{Minimum Spanning Tree (MST)} of a weighted graph. Unlike Prim's, which grows the tree from a single starting vertex, Kruskal's works by sorting \textbf{all edges} by weight and adding them one by one, skipping any edge that would create a cycle.

\textbf{Input:} The graph must be \textbf{undirected} and \textbf{connected}.

\textbf{Output:} An \textbf{acyclic} spanning tree that connects all vertices with the minimum total edge weight.

To efficiently detect cycles, Kruskal's uses a \textbf{Union-Find (Disjoint Set)} data structure. Two vertices share the same \textbf{parent} if they are in the same connected component. Before adding an edge, we check: if both endpoints already have the same parent, adding that edge would form a cycle, so we skip it.

To implement this, we use the following code:
\begin{verbatim}
public class Kruskal {
    class Edge {
        Vertex src;
        Vertex dst;
        int weight;
        Edge(Vertex src, Vertex dst, int weight) {
            this.src = src;
            this.dst = dst;
            this.weight = weight;
        }
    }
    public int minimumSpanningTree(List<Edge> edges, Set<Vertex> vertices) {
        // Build min-heap from all edges (sorted by weight)
        PriorityQueue<Edge> minHeap = new PriorityQueue<>(edges);
        // Each vertex starts in its own component
        UnionFind uf = new UnionFind(vertices); 
        int mstCost = 0;
        while (!minHeap.isEmpty()) {
            Edge edge = minHeap.peek();
            minHeap.remove();
            
            // Pop smallest weight edge
            // If union returns true, src and dst were in different components
            if (uf.union(edge.src, edge.dst)) {
                mstCost += edge.weight; // Add edge to MST
            }
            // If false, same root — skip to avoid cycle
        }
        return mstCost;
    }
}
\end{verbatim}

\begin{itemize}
  \item \texttt{minHeap}: a min-heap built from all edges, always pops the smallest weight edge next
  \item \texttt{uf.union(edge.src, edge.dst)}: attempts to merge the two endpoints. If they already share the same root, it returns \texttt{false} and we skip the edge. Otherwise, it merges them and we add the edge to the MST
\end{itemize}
\textbf{Key Difference from Prim's:} Prim's grows the MST from a single starting vertex using a min-heap. Kruskal's considers all edges globally, building a min-heap and popping them one by one. Prim's asks ``what is the cheapest edge out of the current tree?'' while Kruskal's asks ``what is the cheapest edge overall that doesn't form a cycle?''
\textbf{Time Complexity:}
Building a min-heap from $E$ edges takes $O(E)$. Popping from the heap costs $O(\log E)$, and we pop at most $E$ times, giving $O(E \log E)$. Each \texttt{union} and \texttt{find} operation runs in nearly $O(1)$ amortized time. Since $E \leq V^2$:
\[
O(E \log E) = O(E \log V^2) = O(E \cdot 2\log V) = O(E \log V).
\]

\subsection{Topological Sort}

\textbf{Topological Sort} produces a linear ordering of vertices in a directed graph such that for every edge $u \to v$, vertex $u$ appears before $v$ in the ordering.

\textbf{Requirements:} The graph must be directed and acylic

Note: a topological ordering is \textbf{not necessarily unique}. A graph may have multiple valid topological orderings.

To implement this, we use the following code:

\begin{verbatim}
public class TopologicalSort {
    Map<Vertex, List<Vertex>> adjacencyList;
    public TopologicalSort(Map<Vertex, List<Vertex>> adjacencyList) {
        this.adjacencyList = adjacencyList;
    }
    public List<Vertex> topologicalSort() {
        Set<Vertex> visited = new HashSet<>();
        List<Vertex> output = new ArrayList<>();
        // Run DFS from every vertex to handle disconnected components
        for (Vertex vertex : adjacencyList.keySet()) {
            if (!visited.contains(vertex)) {
                dfs(vertex, visited, output);
            }
        }
        Collections.reverse(output); // Reverse post-order gives topological order
        return output;
    }
    private void dfs(Vertex node, Set<Vertex> visited, List<Vertex> output) {
        visited.add(node); // Mark current vertex as visited
        for (Vertex neighbor : adjacencyList.get(node)) {
            if (!visited.contains(neighbor)) {
                dfs(neighbor, visited, output); // Recurse into unvisited neighbor
            }
        }
        output.add(node); // All descendants processed, add to output
    }
}
\end{verbatim}

\begin{itemize}
  \item \texttt{visited}: tracks which vertices have been visited across all DFS calls
  \item \texttt{output}: collects vertices in reverse topological order (post-order)
  \item The outer loop ensures all vertices are visited, even in disconnected graphs
  \item After DFS completes, we reverse \texttt{output} to get the topological ordering
\end{itemize}

\textbf{Time Complexity:}
The analysis is identical to standard DFS. Each vertex is visited once and each edge is checked once, giving:
\[
O(V + E).
